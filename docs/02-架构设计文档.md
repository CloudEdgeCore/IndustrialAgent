# 工业设备智能诊断与质量分析 Agent 平台
## 架构设计文档

## 1. 架构目标

系统需要同时处理：

- 非结构化工业文档；
- 结构化业务数据；
- 设备时序数据；
- 用户自然语言问题；
- 多步骤 Agent 任务；
- 可追溯分析结果。

设计原则：

- Agent 与数据解耦；
- 工具调用优先于纯 LLM 推理；
- 所有结论尽量有数据证据；
- 支持后续替换模型；
- MVP 可单机部署，后续可扩展。

## 6. Tool Calling 架构

Agent 本身不直接访问数据库。

统一通过 Tool Layer：

```text
Agent
  ↓
Tool Registry
  ↓
Permission Check
  ↓
Tool Executor
  ↓
Data Source
```

优势：

- 控制数据库权限；
- 记录调用日志；
- 防止 LLM 任意 SQL；
- 后续可替换数据源。

---

## 7. SQL Tool

禁止 LLM 直接执行任意 SQL。

推荐流程：

```text
Natural Language
↓
Query Planner
↓
Structured Query
↓
SQL Builder
↓
SQL Validator
↓
Read-only DB
```

例如：

```json
{
  "dataset": "sensor_data",
  "filters": {
    "equipment_id": "EQ-003"
  },
  "metrics": ["temperature", "vibration"],
  "time_range": "last_24h"
}
```

---

## 11. 异常检测

MVP 采用两层：

### 规则检测

例如：

```text
temperature > 85℃
vibration > 7 mm/s
```

### 机器学习检测

可选：

- Isolation Forest；
- One-Class SVM；
- LOF；
- AutoEncoder（后续）。

推荐 MVP 使用 Isolation Forest。

---

## 12. 根因分析

根因结果不是直接让 LLM 猜。

流程：

```text
异常指标
↓
相关变量筛选
↓
时间对齐
↓
相关性分析
↓
历史案例匹配
↓
知识库检索
↓
LLM 综合解释
```

输出：

```text
Root Cause Candidate
Evidence
Confidence
Recommendation
```
